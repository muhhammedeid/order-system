## Application hardening and sending safety

WahaGateway rejects redirects/non2xx responses, preserving the API key on the configured origin. It makes no automatic POST retries. Total HTTP timeout is clamped1–10seconds; connect timeout1–3seconds (`WHATSAPP_CONNECT_TIMEOUT`). One resolution request plus one send remains below the30second job timeout in the normal path; queue retry_after90seconds. An interrupted send is unknown and is not resent. Nonpositive webhook freshness tolerance now fails closed. Default signed/header window300seconds; use bounded provider webhook retries whose total delay fits that window, rather than disabling it.

Automatic owner/customer/campaign sends use durable Database Queue dispatches; core order requests make no provider/network call. Retained manual Admin composer calls remain synchronous and do not participate in core order success. Ambiguous manual sends and empty receipts are now unknown, with an Admin warning to inspect history rather than assume unsent. No automatic resend is added.

Campaign safeguards: subscribed/usable contacts only, at most1000 selected recipients, deterministic template variation, active product/template and consent rechecks, one globally selected recipient per30second scheduler cadence, global worker pacing, confirmed pause/resume, database claim/dedupe, terminal unknown and bounded pre-send retries. These are project controls, not a WhatsApp-approved send-rate guarantee. Do not add account rotation, random delays, spoofing, contact harvesting or other evasion. Start with a small approved internal test audience; keep campaigns in draft until live validation is accepted.

WAHA is not the official WhatsApp Business Platform. Account/session restrictions or bans remain a release risk; low volume/consent cannot guarantee immunity. Obtain the owner's acceptance of this boundary before launch. Keep provider failures isolated from wholesale operations.

## Live checks after separate authorization

1. Verify VPS version/services and loopback-only WAHA/MariaDB listeners; allow public SSH/80/443 only. Validate compose quietly, pull the exact digest, record installed image/version and start the candidate. Keep WHATSAPP_ENABLED=false and all campaigns draft.
2. While WHATSAPP_ENABLED=false, use a private authenticated WAHA API client through secure SSH/local access; Laravel's gateway/Admin provider actions intentionally remain disabled. Create the configured session with webhook events message/message.ack/session.status as supported by the adapter, the real HTTPS endpoint and HMAC key. Keep client credentials in a protected configuration, not URL/command arguments. Do not put a placeholder URL into a live session. Display QR only through that approved private client; do not print it into terminal/session logs. Laravel Admin provider actions become available after the enabled flag is safely activated.
3. Record health, session status through STARTING/SCAN_QR_CODE to WORKING and the actual engine/version. Observe an approved incoming text, stored conversation and signed webhook. Check incorrect HMAC/session/stale timestamp remains rejected.
4. Enable application sending only after readiness and approved-number checks. Verify one text and one image/public-product URL to the approved test recipient; record sanitized message correlation and actual ACK progression. SERVER/DEVICE/READ must be observed individually; do not infer READ support from an HTTP201.
5. Exercise a test order's owner/customer/status/partial/full delivery notifications, then a small test campaign with multiple approved recipients and selected variations. Confirm cadence, pause/resume, failures, unknown no-resend, priority and durable history. No real customer audience is allowed.
6. With campaigns paused, stop WAHA during a test order; prove order persists and pending/failed/unknown states follow documented semantics. Queue retries require the existing safe pre-send boundary; do not bulk retry unknown jobs.
7. Controlled container restart: first pause campaigns and drain/stop outbound worker. Leave volumes intact; never `down -v`. Restart WAHA, observe WORKING/reconnect, then restore worker and resume only after inspection. Repeat a VPS reboot in an approved maintenance window: record Docker restart, Supervisor worker, cron and session recovery. `unless-stopped` intentionally leaves a manually stopped container stopped after reboot.
8. Back up session/media volumes securely before any image upgrade while WAHA and worker are stopped; copy only their actual inspected volume mountpoints. Encrypt/upload the archive off-server. Restore it only into isolated private infrastructure with sending disabled; never attach the same live session concurrently on two workers/hosts. Sessions contain authentication credentials. The default daily application backup covers MariaDB/shared storage, not these WAHA volumes.

If recovery fails, stop outbound work and preserve evidence; do not delete session data, logout, re-pair or automatically resend to conceal failure. Inspect sanitized status/errors, clock, disk and connectivity. Pairing recovery requires the owner; no account action is assumed authorized.
